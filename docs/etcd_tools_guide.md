# etcd 管理工具

在“数据与消息 → etcd 管理”中填写客户端地址（例如 `http://127.0.0.1:2379`），选择 `V2` 或 `V3`，点击“连接”。使用客户端监听端口，通常为 2379；2380 是成员间通信端口。

连接先读取服务端版本，再验证当前目录/前缀的访问。当前每次连接使用一个端点，不自动切换集群成员。地址、凭据和证书文件路径只保留在当前面板会话中，不写入本地配置；SSH 服务器配置复用已有 SSH 工具。

## API 版本与浏览

| 模式 | 协议与列表行为 |
|---|---|
| V2 | REST `/v2/keys`；查询框填写以 `/` 开头的目录，默认 `/`。显示该目录的直接子节点，双击目录进入，点击“上级目录”返回。支持创建目录；不直接编辑或删除目录，避免误删子键 |
| V3 | HTTP/JSON 网关；查询框填写 UTF-8 键前缀，留空查询全部。按服务端版本使用 `/v3alpha`（3.2 及以前）、`/v3beta`（3.3）或 `/v3`（3.4+）。网关必须已开启 |

**v2 和 v3 是独立的键空间**，相同键名可以有不同值。切换 API 前先断开。现代服务端不一定提供 v2；etcd 3.6 已移除 `--enable-v2`，客户端无法为其重新启用 v2。旧版服务端也需要按其版本配置开放 v2 API。

每次默认加载 200 项，可改为 1–10,000。v3“加载更多”使用同一 revision 的分页快照，避免翻页期间写入导致漏项或重复；快照被压缩时需重新加载。v2 没有服务端分页，“加载更多”会重新请求目录并提高显示数量，最多显示 10,000 项；变化期间列表会重新取当前状态。单响应限制 16 MiB，列表累计键值字节限制 32 MiB；v3 列表最多加载 100,000 项，超过限制应缩小前缀。

## 读取、修改和删除

- 单击列表项查看键值，也可点击“新增键”，填写键名后“读取键”精确读取。列表前缀使用 UTF-8；二进制键可在编辑区选择 BASE64 后精确读取。
- 键和值分别支持 UTF8 / BASE64。切换编码会转换已有字节；遇到无效 UTF-8 自动以 Base64 显示，不以替换字符覆盖二进制值。值允许为空，最多 1 MiB；键不能为空。
- “新增键”只在键不存在时创建。编辑已读取的键、删除键时，会比较读取到的修改版本（v2 `prevIndex`，v3 事务比较 `mod_revision`）；冲突时要求重新读取，不覆盖别人的更新。已读取键的键名不能直接修改，创建另一个键需点击“新增键”。
- “删除键”仅删除精确键，需要确认；不会进行前缀范围删除。保存后可刷新列表更新行版本。

TTL 单位为秒：`-1` 保留已有 TTL / lease，新键永久；`0` 永久；正数设置过期时间，最多一年。v3 会建立新 lease 并绑定到该键，保留现有 lease 时不会主动续租；v2 保留 TTL 会按剩余秒数重新计时，不能保证原过期时刻不变。当前工具不提供 lease keepalive、Watch、集群成员管理或事务编辑器。详情中的 v3 TTL 显示 `-1` 表示未单独查询剩余 TTL，lease 字段显示当前租约 ID。

传输异常、超时或取消写入时，结果可能已经生效。程序不会自动重试写入，请重新读取核对。明确返回认证失效时，v3 会重新获取 token 再请求一次；权限不足不会重试。新 lease 在事务明确冲突时撤销，传输结果不明时保留，避免撤销已成功写入的键。

## 认证、HTTPS 与 SSH

在顶部连接区直接勾选“启用 SSH 隧道”并选择服务器，使用方式与 ZooKeeper、Kafka 一致；“认证 / TLS”按钮单独设置用户名、密码、超时和可选 PEM 文件：

- v2 使用 HTTP Basic 认证；v3 使用 `/auth/authenticate` 获取 token。没有认证时用户名留空。需要限制键范围的用户可在连接前先填写有权限的目录/前缀。
- HTTPS 默认验证服务端证书链和域名。私有 CA 可选择 CA PEM；双向 TLS 同时选择客户端证书链与未加密 PKCS#1/PKCS#8 PEM 私钥。没有“跳过证书验证”选项。证书用于 TLS 握手；v3 JSON 网关不支持以客户端证书 CN 替代用户名/密码完成 API 认证。
- 勾选“启用 SSH 隧道”，选择在“SSH 终端”中保存的服务器。这里的 etcd 地址填写 **SSH 服务器能够访问的地址**，例如 `http://127.0.0.1:2379` 表示 SSH 主机本地的 etcd。
- SSH 列表与 ZooKeeper、Kafka 共享 `SshConfigStore`，配置变化后自动更新并保留所选服务器；建立连接及已连接期间锁定隧道开关和服务器选择，断开后恢复编辑。连接状态显示所用 SSH 服务器。
- 隧道仅绑定本机 `127.0.0.1` 的临时端口，复用既有 SSH 凭据和主机指纹确认。通过 SSH 使用 HTTPS 时，TCP 走本地转发，TLS 继续验证原始 etcd 域名并发送相应 SNI，不需要为本地转发端口更换服务端证书。

“取消请求”会发出中断和断开当前 HTTP 请求，等待工作线程退出后才允许下一次操作。连接超时可设为 1–60 秒。断开、失败和应用关闭时均释放面板持有的 SSH 转发；不会主动关闭其他工具持有的隧道。

## 协议资料与验证

实现依据官方 [v2 REST API](https://etcd.io/docs/v2.3/api/)、[v3 JSON 网关](https://etcd.io/docs/v3.6/dev-guide/api_grpc_gateway/)及 [RPC 定义](https://github.com/etcd-io/etcd/blob/main/api/etcdserverpb/rpc.proto)。v2 服务端限制见 [升级到 3.6](https://etcd.io/docs/v3.6/upgrades/upgrade_3_6/)。不新增 etcd SDK，使用 JDK HTTP/TLS、现有 Jackson、Bouncy Castle 和 SSH 组件。

本机已使用临时数据目录与回环端口，在官方 etcd 3.5.34 上验证 V2/V3 直连及经真实 SSH 通道转发的增删改查、TTL、版本冲突与分页；启用 v2 Basic / v3 token 认证后也完成了真实读写。未访问用户的 etcd 集群。回归另覆盖 Base64、认证 token 刷新、HTTP 状态、取消后的旧结果丢弃，以及转发后原始 TLS 域名验证。测试服务与临时隧道均在验证后关闭。

```powershell
mvn -B -o "-Dtest=EtcdClientTest,EtcdPanelTest,EtcdHttpTransportTest,EtcdTlsTest,ToolCatalogLabelsTest,I18nResourceTest,I18nHardcodedTextTest" test
mvn -B -o verify
```
