# 功能路线图

本文档记录架构重写完成后可评估的新增能力。它是优先级和边界清单，不承诺发布日期，也不代表任何外部服务一定可用。所有条目在实现前都必须先完成工具目录、分类、本地化、生命周期和文档登记。

## 优先级规则

- P0：优先复用现有面板和领域服务，待 `catalog` 与 `infra` 层稳定编译后评估。
- P1：依赖共享网络、安全或容器服务，必须先建立可复用的连接、鉴权、超时和取消语义。
- P2：依赖稳定的插件、自动化或工作区契约，待扩展边界明确后再评估。
- 路线图不改变当前运行时行为；新增功能必须先定义稳定 ID、分类、本地化键、配置迁移和资源关闭策略。

## P0：基础工作台能力

| 功能 | 目标分类 | 依赖与首个交付切片 |
|---|---|---|
| OpenAPI / Swagger 工作台 | 网络与接口 | [已完成] 复用 HTTP 客户端和请求模型；支持导入 OpenAPI 3、参数编辑、cURL 导出和在线调试 |
| JSONPath / JMESPath 查询 | 编码、转换与文本 | [已完成] 引入 Jayway JsonPath；支持表达式提取、切片过滤、路径列表模式与错误定位 |
| YAML / TOML / INI 转换与校验 | 编码、转换与文本 | 扩展格式转换器；先实现 YAML 与 Properties/JSON 的双向转换及语法诊断 |
| 文件批量摘要与签名校验 | 安全与身份 | [已完成] 多文件/目录并发流式计算 MD5/SHA-256/SM3、校验清单核对与数字签名验签 |
| CSR / PKCS#12 / 证书链检查 | 安全与身份 | [已完成] CSR 签名请求解析与自验签、PKCS#12 密钥库导入导出及证书链拓扑诊断 |
| DNS / TLS / HTTP 诊断 | 网络与接口 | 依赖共享网络资源层；先输出 DNS、TLS 证书和 HTTP 时延的分阶段结果 |
| 日志查看与过滤器 | 系统与自动化 | 依赖流式文件读取；先支持大文件分页、实时追踪、正则过滤和高亮 |
| 工作区导入导出 | 系统与自动化 | 依赖配置契约；先保存工具配置、请求模板和常用输入，并提供版本字段 |

## P1：协议与运维协作

| 功能 | 目标分类 | 依赖与首个交付切片 |
|---|---|---|
| GraphQL 客户端 | 网络与接口 | 依赖共享 HTTP 请求模型；先支持 Schema 导入、查询变量和响应树 |
| gRPC 客户端 | 网络与接口 | 依赖协议资源层；先支持 proto 导入、Unary 调用和元数据配置 |
| OAuth2 / OIDC / JWK 工具 | 安全与身份 | 依赖统一密钥和令牌模型；先支持授权码流程解析、JWK 查看和 JWT 验证 |
| Git 仓库辅助工具 | 系统与自动化 | 依赖外部进程生命周期抽象；先支持状态查看、差异预览和常用命令模板 |
| Docker / K8s Manifest Diff 与 Port Forward | 云原生与运维 | 依赖 K8s/容器连接服务；先提供 YAML 结构差异和端口转发会话管理 |
| XPath / XSLT 工具 | 编码、转换与文本 | 复用 XML 模型和错误定位；先支持 XPath 查询与 XSLT 单次转换 |
| Webhook 签名验证器 | 安全与身份 | 依赖 HMAC/公钥摘要服务；先支持常见签名头解析和重放窗口提示 |
| Cron 可视化编辑和冲突检测 | 系统与自动化 | 复用 Cron 解析器；先提供字段编辑、未来执行时间和任务冲突检查 |

## P2：平台扩展与协同

| 功能 | 目标分类 | 依赖与首个交付切片 |
|---|---|---|
| 插件 SDK 与插件目录 | 系统与自动化 | 依赖稳定的 descriptor、生命周期和权限边界；先加载只读元数据 |
| 自动化脚本/宏执行器 | 系统与自动化 | 依赖工作区和取消语义；先提供受限步骤编排与执行日志 |
| OpenTelemetry Trace 查看器 | 监控与远程协作 | 依赖统一导入模型；先支持 OTLP/JSON 文件导入和 Trace/Span 时间线 |
| 系统密钥链集成 | 安全与身份 | 依赖跨平台凭据适配层；先实现凭据读取、写入和不可用时的明确降级 |
| 配置版本历史与差异恢复 | 系统与自动化 | 依赖工作区存储和原子文件策略；先保留版本快照、差异预览和恢复确认 |
| 多窗口/标签页工作区 | 系统与自动化 | 依赖稳定工作区状态模型；先支持同一工具多实例和标签页恢复 |

## 评估门槛

每个条目进入实现前，都要完成以下检查：

1. 在 `ToolCatalog` 中定义稳定 descriptor、目标分类和搜索关键词。
2. 在默认、中文和英文资源中提供完整标签，并确认兼容键不被删除。
3. 明确 UI、应用编排、领域模型和 `infra` 适配器的依赖方向。
4. 定义配置、凭据、线程、取消和关闭语义，并补充使用文档。
5. 先通过编译、静态资源键一致性和 `git diff --check`，再安排针对性功能验证。
