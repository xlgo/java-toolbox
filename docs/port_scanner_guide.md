# 批量端口扫描

入口为“网络与接口 → 端口扫描与网络诊断”。这是 TCP connect 扫描器：对指定 IP 的端口尝试建立连接，不发送业务请求，不以 Ping 成功作为扫描前提。

## 目标和端口

目标框可混用多个 IPv4/IPv6、范围、CIDR、域名和 IPv4 末尾通配符，以逗号、分号、空白或换行分隔。点击“批量编辑”可逐行输入，也可用“导入目标”读取 UTF-8 TXT。

```text
192.168.1.10-20
192.168.1.250-192.168.2.20
10.20.30.0/24
server-a.example.internal
::1
2001:db8::1-2001:db8::f
2001:db8::/124
192.168.10.*
```

范围包含两端；`192.168.1.10-20` 包含 11 个地址。IPv4/CIDR 重叠和域名解析到相同 IP 时去重，每个 IP+端口只探测一次。域名仅在开始时解析，预览计划不发 DNS 请求；一个域名解析失败只生成一条诊断结果，其他目标继续。

CIDR 会归一化到网段。默认不扫描常规网段首尾，`/24` 是 254 个地址；在“扫描配置 → 目标主机 / IP 段”中可启用包含首尾。`/31` 保留两个地址，`/32` 保留一个。显式范围不额外去掉 `.0` 或 `.255`。预览计划的提示中可查看归一化后的首末地址。

“扫描配置”中也可填写排除目标，支持相同表达式；排除 CIDR 覆盖整个范围，包括首尾。排除域名不能解析时任务报错且不开始 TCP 探测，避免无意忽略排除规则。目标与端口分开填写，不接受 `192.168.1.2:80` 这样的混合输入。

IPv6 CIDR 包含范围内全部地址，不套用 IPv4 的首尾排除规则；例如 `/124` 为 16 个地址，`/127` 为两个、`/128` 为一个。地址区间先做并集和排除，再检查目标预算，`::/0`、`/64` 等大段不会先展开；预算允许时只展开最终剩余范围。带 zone 的 IPv6 保留并规范化接口标识，不把不同接口的地址合并。IPv4-mapped 的单地址按 IPv4 去重，mapped IPv6 CIDR/范围目前应改用 IPv4 表达式。IPv4 通配符仅支持连续末尾段，如 `192.168.10.*`、`10.20.*.*`，不支持 `192.168.*.10`。

目标文件最多 1 MiB，允许 UTF-8 BOM、整行 `//` 注释、`#` 注释和空行。导入和批量编辑都先验证，再替换目标；非法内容不会覆盖原输入，也不会自动扫描。

“追加端口”支持离散列表与范围混输，例如：

```text
22,80,443,2379,2380,8080-8085,9092,9093
```

这组为 13 个唯一端口。端口必须在 1–65535；非法项和反向范围报错，不会静默跳过。选择的端口组与追加端口取并集，然后减去“排除端口”。只扫描自定义列表时，在“扫描配置 → 端口组”点击“取消全部组”。

预设有 Web/应用、数据库、缓存/搜索、消息/注册协调、远程/文件访问、邮件/目录、容器/可观测性七组，标签显示数量并展示完整列表，可同时选择。支持全部 TCP 端口快捷项和保存、编辑、重命名、删除自定义端口组。预设、追加端口及排除端口重复的部分不重复扫描。用途名称只是端口号提示，不能据此确认服务软件。

## 超时、并发和预算

“扫描配置 → 高级参数”中设置：

| 参数 | 默认 | 范围/含义 |
|---|---|---|
| 连接超时 | 500 ms | 50–60,000 ms，每次 TCP 连接的等待上限 |
| 全局并发 | 64 | 1–256，设为 1 即串行 |
| 单主机并发 | 8 | 1–64，且受全局并发约束 |
| 每秒最多连接数 | 200 | 1–10,000，限制新探测提交速率 |
| 目标预算 | 4,096 | 可提高至 65,536 个去重后的 IP |
| 探测预算 | 1,000,000 | 可提高至 100,000,000 次，等于目标数×端口数 |
| 结果缓存 | 256 MiB | 16–1,024 MiB，达到预算停止并保留已保存结果 |

点击“预览计划”查看已确定的 IP 数、端口数、探测数、待解析域名数和耗时估算。例如 `192.168.1.0/24` 配上述 13 个端口，默认是 **254×13=3,302 次**。域名解析后的实际 IP 数仍需通过预算检查，检查完成前不启动 TCP 探测；域名解析的单项等待至少 1 秒，最多采用配置的连接超时。系统 DNS 可能不可中断，但迟到的解析结果不会进入已取消会话。

调度按主机轮转，任务不一次性全部排队，排队和在途数量有界。限速使用配额调度，允许不超过全局并发且约 50 ms 配额的小批启动，实际速度受操作系统、网络和存储影响，不保证达到设定上限。点击配置弹窗“完成”即可保存超时、并发、速率、端口和端口组等偏好，无需先扫描；输入有误会在弹窗内提示。

页面支持命名扫描方案的保存、加载和删除，最多 100 个。显式保存方案时会保存目标、排除目标、有效端口集合、CIDR 选项及高级参数；加载只恢复输入，不进行 DNS 查询或扫描。方案把当时选中的端口组与追加、排除端口合成为固定有效端口表达式，因此即使以后修改/删除端口组，原方案范围也不会改变。未显式保存方案的目标和排除目标仍只保留在当前面板。

## 结果和停止

左侧显示每个目标的已探测数、开放数和非开放数；点击主机筛选明细，点击“全部主机”恢复。右侧每页最多 500 行，展示原目标、实际 IP、端口、协议、状态、TCP 连接耗时、用途提示和失败原因。

- 默认只显示开放结果，可切换全部状态、连接失败、超时、不可达、解析失败等。主机解析失败记录的端口为 0，代表尚未执行端口探测。
- 连接失败保留系统原因。超时既不表示端口已关闭，也不能确定是防火墙拦截。连接耗时不同于 Ping RTT。
- 全部结果保存在本次临时 SQLite 缓存中，界面只显示当前页，不会将百万条结果堆入表格；主机汇总包含未完成主机。DNS 失败按主机单独列示。
- 停止会阻止后续调度、主动关闭当前 Socket，并结束会话。已经完成并进入结果队列的探测会继续收取和落库；被取消的在途/未执行探测不保证逐条记录，不会伪造“关闭”状态。停止完成前不能启动另一批。
- 扫描中禁用清空和导出。停止或完成后可查看、筛选、复制和导出；开始新扫描会释放上一轮结果缓存。关闭工具箱会清理当前临时文件；异常退出时可能留下缓存文件。

“复制开放端点”复制当前主机/文本筛选下的开放结果，格式为 `IP:端口`，IPv6 为 `[IPv6]:端口`，最多 1 MiB；更多结果请导出。复制执行中按钮暂时禁用，避免重复排队，剪贴板占用等失败不会使按钮永久失效。

选中一条开放结果，点击“诊断所选”可打开现有 DNS/TLS/HTTP 工具。TLS 主机使用实际探测的 IP，原目标是域名时预填为 SNI；HTTP 预填实际 IP 的 URL，可按服务需要调整 Host/域名。打开窗口不会自动执行诊断，需在对应页点击请求；关闭时取消其任务。当前是单条结果交互诊断，不是批量 Banner 或协议识别。

CSV/JSON 可选择当前筛选或全部结果，与当前页无关。JSON 附带扫描参数、完成阶段、总数和筛选条件；CSV 包含逐条扫描数据及超时、并发、速率、批次总数和完成阶段，文本字段进行公式保护。导出先写同目录临时文件，成功后替换目标，失败时不破坏已有文件。缓存达到预算时可能有已探测但未保存的最后一批，导出以已保存结果为准。

## 后续范围

IPv6 网段/范围、TXT 导入、命名方案和单端点诊断入口已在功能检查后补齐。自动反向 DNS、批量协议/Banner 识别、快照对比与失败项重试仍属后续范围；UDP 不是本次 TCP 扫描的一部分。实现与验收规划见 [设计文档](superpowers/specs/2026-10-16-batch-port-scanner.md)。IPv6 的 128 位地址及无广播语义依据 [RFC 4291](https://www.rfc-editor.org/rfc/rfc4291.html)，接口作用域参考 [RFC 4007](https://www.rfc-editor.org/rfc/rfc4007.html)。

```powershell
mvn -B -o "-Dtest=ScanExpressionTest,ScanSessionTest,ScanResultRepositoryTest,TcpConnectProbeTest,PortScannerPanelTest" test
mvn -B -o verify
```
