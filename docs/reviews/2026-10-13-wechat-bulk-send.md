# 微信群发优化与验证（2026-10-13）

原群发用全局快捷键、剪贴板和固定等待时间控制微信，要求客户端一直处于前台；按键执行完毕即标记成功，无法证明目标会话产生了发送记录。

默认模式改为文本后台核验：通过 UI Automation 定位联系人和输入框，用 ValuePattern 写入并完整读回文本，导航后允许微信最小化或其他应用保持前台，最终 Enter 仅投递到微信窗口。定位时仍需短暂显示微信，当前实现不支持锁屏或无人登录桌面。

发送前唯一验证当前进程的账号与数据库密钥。在输入核对后记录各消息分片的 local_id 基线，再只读核对目标会话的新记录、完整文本、文本类型、本机 origin_source=1、通过分片 Name2Id 映射的当前账号发送者。仅唯一记录满足 status=2 且 server_id>0 才显示“已确认发送记录”；不代表收件方收到或已读。

待确认、未确认、已确认及兼容模式已触发的行不会自动重发。重复显示名称、无法唯一定位的搜索结果和已有草稿会跳过。停止后等待助手退出和窗口恢复，才允许启动下一批。Qt 无障碍控件树未开启时，仅临时切换已验证的进程数据状态，并在正常退出、取消时恢复；客户端和数据库文件不修改，无 OCR 模型。

保留图片和 Ctrl+Enter 的前台兼容模式，状态调整为“已触发（未核验）”。发送助手、联系人助手共用 Python 启动检测，均从 JAR 解包到临时目录运行。计划与事件通过进程管道传递，密钥、数据库快照保留在内存。

## 真实验证

- Windows 11、微信 4.1.13.65、64 位 Python 3.14.5。
- 仅向用户明确授权的两个微信号测试，累计四条文本消息；一名联系人为当前登录账号自身。未向其他联系人发消息。
- 验证微信最小化、其他应用处于前台时的定向发送；原前台应用保持不变。新助手完整批次确认 2/2，两个会话均有新 local_id、status=2、正数服务器 ID，进程退出码为 0。
- 强制禁用最近聊天捷径，以两个授权微信号分别验证搜索路径；实际输入框标题匹配，未额外发送。发现 Qt Select 和搜索框 Enter 无法可靠打开目标，改为点击唯一匹配结果并重新核对标题。
- 禁用微信号检索，以唯一显示名称验证没有 alias 的搜索路径成功，未发送。
- 初始化完成后的取消测试使用 dry_run，正常退出、无发送；停止到退出约 0.24 秒，Qt 无障碍状态恢复为原值。
- 用户账号、消息正文、具体消息 ID、密钥和原始数据库均未写入项目验证记录。

## 自动回归与打包

Python：`python -B -m unittest discover -s tools/tests -v`，30 个用例通过。覆盖只读解密、WAL、联系人解析、非好友同名冲突、收发记录区分、旧记录排除、分片发送者映射、确认条件、重复记录、取消、草稿保护和控件搜索。

Java：使用 JDK 17 执行 `mvn -B -o verify`，2,509 项测试，失败 0、错误 0、跳过 1；fat JAR 打包与依赖声明分析通过。之后针对兼容模式跳过待确认/未确认记录的统计调整，重新执行微信及国际化相关定向 verify，23 项全部通过。

最终 JAR 包含五个微信助手脚本，逐个比对与工作区源码一致；发送服务与 Python 启动器的 class 为 JDK 17 编译，群发面板 class 与最终编译产物一致。

启动最终 JAR 的实际主窗口并打开群发助手，确认默认选中文本后台核验、发送队列为空，窗口正常响应；预览启动未触发发送。

## 待发列表布局与删除

发送参数和全局图片移入“群发配置”弹窗，关闭后保留设置。主页面取消附件分栏，列表使用完整高度与约四分之三宽度；配置、开始和停止仍可直接操作。新增“删除选中”及 Delete 键，支持 Ctrl/Shift 多选，按模型索引倒序移除并重新编号，保留其他行的消息内容及核验状态；发送和停止清理期间禁止删除及打开配置。

微信和国际化定向 verify：24 项通过，打包与依赖声明检查通过。回归覆盖排序后非连续多行删除、ID 重编号、键盘删除及发送期间拦截。最终界面以 1,260×780 和 960×640 的独立测试窗口检查，待发表格视区分别为 897×466 和 672×326，可展示约 17/12 行；配置弹窗、设置保留及实际多选删除均通过，验证过程没有发送消息。

将图片选择器的所属窗口调整为配置弹窗后，UI 与国际化 11 项复验通过，最终 JAR 重新打包且助手资源与编译类校验通过。

## 当前边界

仅支持 Windows 文本 Enter 发送；导航仍会短暂使用前台和控件点击。不同微信版本需重新验证控件与数据库结构。只接受唯一主窗口和唯一账号，没有多账号选择器；单数据库文件/WAL 快照上限 128 MiB。联系人同名时跳过，草稿不会覆盖。结果不明时需要查看实际聊天，程序不盲目重发；清空或重导列表不保留跨批去重状态。

控件资料参考 [uia_driver.py](https://github.com/fanyuantaier/wechatauto-replica/blob/main/wechatauto/uia_driver.py)，密钥结构参考 [db.py](https://github.com/fanyuantaier/wechatauto-replica/blob/main/wechatauto/db.py)，页认证与 WAL 依据 [SQLCipher](https://www.zetetic.net/sqlcipher/design/)和 [SQLite](https://sqlite.org/fileformat2.html#walformat)。
