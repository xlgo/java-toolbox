# etcd 工具实现与验证（2026-10-16）

工具登记为 `etcd.management`，归属数据与消息分类，默认/中文/英文资源完整。连接和编辑操作在单独守护工作线程中执行，关闭时取消请求、丢弃过期连接结果并释放面板持有的 SSH 隧道，不保存本次连接凭据。

实现包括 v2 REST 和 v3 HTTP/JSON 网关，按服务端版本适配 alpha/beta/稳定网关路径；键值浏览、精确查询、创建、带修改版本比较的更新/删除、TTL、UTF8/Base64 切换、账号认证以及 HTTPS/mTLS。SSH 复用现有服务器配置、凭据和指纹策略，使用回环地址临时端口；TLS 仍校验原始目标主机身份，未关闭证书检查。没有引入 etcd SDK 或增加 Maven 依赖。

v2 以目录浏览且不直接删除目录，v3 以 revision 固定的前缀范围分页。请求/响应/列表字节有界，超时和取消后不盲目重发。新 TTL lease 仅在明确事务冲突时撤销，传输结果不明时不撤销，防止误删已写入键。

## 隔离环境实测

从官方 etcd-io/etcd release 获取 3.5.34 Windows x64 包，SHA-256 与官方发布资产元数据一致后执行。测试使用临时数据和配置目录，仅监听 `127.0.0.1`；未连接用户集群或使用用户 SSH 凭据。SSH 服务为本机临时测试实例，使用随机临时凭据。

以下四种连接均完成新增、读取、修改、删除、TTL 保留及清除、陈旧版本拒绝和列表加载：

| API | 路由 | 结果 |
|---|---|---|
| v2 | 直接 HTTP | 通过 |
| v3 | 直接 HTTP | 通过 |
| v2 | JSch SSH direct-tcpip 转发 | 通过 |
| v3 | JSch SSH direct-tcpip 转发 | 通过 |

v2 特殊字符键名和 Unicode 值、v3 二进制值与 revision 分页均完成真实往返；测试随后启用 v2 Basic 和 v3 token 认证，再次完成两套 API 的实际读写。所有临时 etcd/SSH 服务和隧道均关闭。

## SSH 入口对齐

SSH 开关和服务器下拉移到顶部连接区，与 ZooKeeper、Kafka 使用相同的可见连接行；认证/TLS 弹窗只保留 etcd 账号、超时和证书。服务器列表继续共享 `SshConfigStore`，转发继续共享 `SshTunnelBridge`，不新增独立 SSH 密码或私钥配置。开始连接后及已连接时锁定 SSH 开关和服务器选择，断开后恢复；状态显示实际选中的 SSH 服务器。

回归增加两套 API 传递所选 SSH 配置 ID、连接期间路由锁定和断开后恢复的验证，并与 ZooKeeper 的服务器列表逐项比较。JDK 17 定向 verify 共 29 项全部通过，打包和依赖声明检查通过。实际窗口中 SSH 连接行可直接操作，认证/TLS 弹窗不再重复放置 SSH 控件；最终 JAR 的编译类和语言资源校验通过，预览窗口已更新。

## 边界

当前使用单端点，无成员自动故障转移、Watch、keepalive 或管理角色权限的界面；本次连接参数不持久化。v2/v3 键空间相互独立；服务端需提供相应 API，etcd 3.6 不提供 v2。v2 无服务端分页，会重新获取目录后限制显示数量。请求 2 MiB、值 1 MiB、响应 16 MiB、累计列表 32 MiB；需浏览更多内容时缩小目录或前缀。其他版本的实际服务端未逐一实测。

具体操作与官方协议来源见 [etcd 指南](../etcd_tools_guide.md)。
