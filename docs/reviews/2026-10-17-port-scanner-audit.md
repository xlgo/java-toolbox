# 扫描工具功能复查与补充（2026-10-17）

按第一批规划、已交付行为和日常批量扫描流程检查。范围是 `port.scanner` 及其到现有网络诊断工具的连接，不改变此前 etcd 和 SSH 工具的实现。

| 检查项 | 发现与处理 |
|---|---|
| 配置保存 | 原来仅开始扫描时写偏好，改为配置弹窗“完成”即可校验并保存，错误显示在弹窗内，无需发起扫描 |
| 停止完整性 | 停止前已完成但仍在完成队列的结果可能被丢弃；现在结束工作线程后排空已完成结果并落库，不为取消/未执行的任务伪造状态 |
| 复制任务 | 重复点击可继续排队，剪贴板异常也可能使按钮失效；增加单任务保护和 finally 恢复 |
| 批量输入 | 增加 UTF-8 TXT 导入、BOM/注释处理和 1 MiB 文件限制；非法输入保留原目标；预算应用排除规则后再判断 |
| IPv6 | 增加范围、CIDR、并集/排除和 128 位计数；大范围先检查预算，不先枚举地址；规范化 scope，避免同接口重复及不同接口混合 |
| IPv4 通配符 | 支持连续末尾通配符，如 `192.168.1.*`、`10.20.*.*`；不支持中间通配符表达式 |
| 扫描方案 | 增加显式保存、加载、删除；保存有效端口集合和参数，不依赖之后仍存在的自定义端口组；加载不会自动联网 |
| 端口组保存 | 保存新组时预填当前组合的有效端口，不再只取“追加端口”中的文本 |
| 诊断流程 | 增加“诊断所选”，开放结果可带入现有 DNS/TLS/HTTP 页面；TLS 保留实际 IP 与域名 SNI，用户点击后才请求 |
| 方案名称边界 | 列表占位项与方案使用独立对象，方案名称与占位文案相同也可正确选择 |

## 验证

- 首轮 42 项定向测试通过；覆盖 IPv6 范围/CIDR、scope、巨大区间排除后计数、通配符、TXT 编码/大小边界、配置不扫描即可保存、方案往返、诊断预填和取消时已完成结果保留。
- JDK 17 全量 `mvn -B -o verify`：2,558 项测试，失败 0、错误 0、跳过 1；打包与依赖声明分析通过。
- 真实本地 UI 输入两个 IPv4 回环地址、IPv6 `/128` 和重复 IPv6 范围，最终去重为 3 个主机、6 次探测，找到两个真实监听端点；诊断窗口打开及关闭正常，没有自动执行诊断。
- 最终 43 项定向 verify 全部通过（失败、错误、跳过均为 0），JAR 打包和依赖声明检查通过。扫描器、IPv6/方案模型、目标导入及网络诊断类与最终编译产物一致，三份语言及端口预设资源与源码一致，class 格式为 JDK 17。新版已打开至扫描页面，初始没有扫描会话。

## 明确保留的边界

这次补齐了原规划中 IPv6 段、TXT 导入、命名方案和单端点诊断的部分第二批能力。自动反向 DNS/主机标签、批量 Banner/协议识别、历史快照对比及失败项重试尚未实现；UDP 不在当前 TCP 扫描范围。IPv4-mapped IPv6 CIDR/范围请用 IPv4 表达式，IPv6 链路本地地址需要正确的接口 scope。完整使用方式见 [扫描指南](../port_scanner_guide.md)。
