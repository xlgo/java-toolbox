# Java Toolbox 全功能审查与修复设计

## 背景

Java Toolbox 当前包含 44 个工具入口、136 个主源码文件和 34 个测试文件。2026-08-07 的基线验证运行了 173 个测试，全部通过；这说明已有测试覆盖的行为稳定，但不能证明全部工具的交互、异常路径、最小窗口布局、主题切换、语言切换和资源关闭都正确。

本轮进行一次完整审查、统一修复和一次性交付。验证不连接真实生产或个人外部环境；需要网络、账号或集群的功能使用纯逻辑测试、本地临时端点、拒绝连接和资源生命周期测试覆盖可离线证明的部分。

## 目标

1. 为 44 个工具建立可追踪的审查矩阵，确认每个入口可构造、可导航、可关闭。
2. 检查每个工具的核心离线行为、输入边界、异常反馈和资源生命周期。
3. 在默认窗口和 820×520 最小窗口下检查布局可达性，并覆盖浅色/深色主题和中英文壳层。
4. 优先修复共享根因，再修复工具独立问题，避免形成互不一致的局部方案。
5. 每个行为修复先增加能正确失败的回归测试，再写最小实现。
6. 保持全部现有工具、稳定工具 ID、配置键、已保存数据格式、主题、语言和 Java 8 目标兼容。

## 非目标

- 不连接真实 Redis、数据库、Kafka、ZooKeeper、Kubernetes、SSH、微信或远程桌面环境。
- 不以缺少真实环境为由模拟“连接成功”；无法离线证明的能力明确标记为条件验收。
- 不删除、合并或隐藏现有工具。
- 不改变已有配置键、加密库格式、连接配置格式或用户数据迁移约定。
- 不为统一视觉而重写已经正确的业务流程。
- 不引入与 Swing/FlatLaf 设计体系冲突的网页式组件或装饰性动画。

## 审查范围

### 全局工作台

- `MainFrame`、`ToolSidebar`、`ToolNavigationModel`、`ToolNavigationState` 和 `ToolContentHost`。
- 导航、搜索、侧栏收起/展开和宽度持久化。
- 当前工具面包屑、主题、语言和状态栏。
- 启动、窗口位置恢复、最小尺寸和关闭时资源释放。

### 共享 UI 组件

- `Tokens`、`Layouts`、`Card`、`FormGrid`、`ActionBar`、`Buttons`、`Fields` 和 `KitBorders`。
- 间距、控件高度、卡片边界、字体、语义颜色、键盘焦点和中英文文本宽度。
- 容器在缩小时的可达性、滚动策略和首选尺寸约束。

### 44 个工具入口

- 加密安全：摘要与编码、对称加密、非对称加密、密码管理器、Google 身份验证器、证书管理。
- 转换与格式：进制编码、时间戳、Base64 图片、格式转换、JSON、XML、SQL、字符串工具。
- 开发与连接：正则、JWT、Cron、文本对比、Docker Compose、子网、HTTP、回调、颜色、K8s 部署、K8s 管理、Redis、数据库、Kafka、ZooKeeper、微信群发、SSH。
- 生成与计算：UUID、密码、随机数据、计算器、统计。
- 算法与图表：排序、查找、汉诺塔、BPMN、Mermaid、流程图。
- 监控与远程：视频监控、远程桌面。

## 审查矩阵

每个工具至少记录以下五类结果：

1. **可构造**：在 Swing EDT 创建视图，不执行非必要的网络连接，不抛出异常。
2. **可操作**：核心输入、主操作和结果区域可到达；确定性工具至少有一个有效输入输出样例。
3. **边界正确**：空输入、非法输入、超长输入或无选择状态得到明确反馈，不使 EDT 崩溃。
4. **布局稳定**：正常与最小内容尺寸下不存在负尺寸、关键操作不可达、文本被固定宽度截断或不合理的嵌套滚动。
5. **资源安全**：计时器、线程、连接、剪贴板、临时文件和监听器在锁定、切换或关闭时正确停止或释放。

审查结果按严重度处理：

- P0：数据泄露、破坏或安全边界错误，立即修复。
- P1：崩溃、死锁、EDT 阻塞、核心功能不可用或资源泄漏，必须修复。
- P2：最小窗口不可达、主题/语言错误、明显布局冲突或误导性反馈，必须修复。
- P3：低影响一致性或视觉细节，在不扩大范围时修复。

## 技术结构与修复边界

### 审查支持层

测试代码维护稳定工具清单和审查矩阵。它负责：

- 使用临时配置根目录和临时安全库构造主窗口。
- 遍历稳定工具 ID，触发惰性视图创建并确认导航映射一致。
- 在 EDT 上设置正常和最小内容尺寸、执行递归布局并检查非法几何状态。
- 为确定性工具调用可测试的纯逻辑入口。
- 为连接型工具使用回环地址、本地临时服务器或立即拒绝的端口验证失败路径。
- 将无法离线证明的真实服务成功路径保留为条件验收项。

审查支持代码只位于测试目录或 `target` 生成目录，不进入生产界面，不修改用户配置。

### 共享根因层

重复出现在多个页面的问题优先修改 `com.aqishi.toolbox.ui` 或 `com.aqishi.toolbox.ui.kit`：

- 主框架层负责全局导航、状态、主题、语言和窗口边界。
- UI kit 负责尺寸、间距、字体、颜色、按钮、字段、卡片和通用布局行为。
- 共享修复不得改变工具业务数据流。

### 工具独立层

单个工具的解析、计算、协议、校验或异步任务问题保留在对应面板或提取到同包纯逻辑类：

- UI 面板只负责收集输入、触发任务、显示结果和反馈状态。
- 确定性逻辑优先通过无 Swing 依赖的方法或类测试。
- 网络操作不得在 EDT 阻塞；取消、失败和关闭路径必须恢复控件状态并释放资源。
- 不为测试向生产类加入仅测试使用的公开方法。

## 数据与交互流程

1. 测试使用临时 `ApplicationPaths` 安装隔离配置，避免读写用户真实配置。
2. 构造共享 `VaultService` 和 `SecureClipboard`，再构造 `MainFrame`。
3. 从导航模型取得全部稳定工具 ID，逐个切换并创建视图。
4. 对每个视图执行构造、几何、可访问名称和关键控件检查。
5. 对纯本地工具运行固定输入输出与边界样例。
6. 对连接型工具验证输入校验、连接拒绝、超时/取消边界和关闭资源；不访问真实服务。
7. 每个确认问题先增加失败测试，然后在正确责任层完成最小修复。
8. 全部局部修复完成后运行完整测试、打包和视觉截图检查。

## 错误处理规范

- 用户可修正的输入错误使用清晰、本地化的提示，不向用户展示原始堆栈。
- 异步任务失败必须回到 EDT 更新界面，并恢复被禁用的主操作。
- 网络错误区分参数无效、连接失败、超时、取消和协议错误；无法区分时使用安全的通用提示并保留日志诊断信息。
- 锁定安全库后，敏感内容、计时器和剪贴板状态按现有安全策略清理。
- 关闭主窗口时停止状态计时器、SSH、ZooKeeper、HTTP 和其它已创建的后台资源。
- 未选择数据时禁用依赖选择的操作，避免以异常代替正常空状态。

## 布局与视觉规范

- 全局框架参考用户提供的效果图调整品牌区、搜索框、导航图标、面包屑、主题/语言图标和状态栏；安全库操作仍保留在加密页面内部。
- 颜色通过 `UIManager` 和 `Tokens` 推导，不硬编码只适用于浅色主题的壳层颜色。
- 常规控件保持 32px 高，导航行保持紧凑，按钮文本在中英文切换后不被截断。
- 工具页继续采用“配置 → 操作 → 结果”的共享结构；内容区只由 `Layouts.page()` 提供一层外边距。
- 820×520 下允许内容滚动，但全局导航、主要操作和当前上下文必须可到达。
- 选中、错误、警告和成功状态不只依靠颜色表达；焦点状态必须可见。

## 测试策略

### 基线与回归

- 保留当前 173 个通过的测试作为基线。
- 每个确认的功能错误、布局根因或生命周期问题都增加独立回归测试。
- 严格执行红—绿—重构：先观察测试因目标问题失败，再写最小实现并运行局部与相关测试。

### 自动化审查

- 工具清单测试保证 44 个稳定 ID 无重复、无遗漏，导航和内容宿主可定位同一实例。
- 全视图构造测试保证每个工具能在 EDT 惰性创建。
- 布局健全性测试检查正常/最小尺寸下的负尺寸、越界和关键操作不可达信号。
- 资源生命周期测试覆盖主窗口关闭和可离线构造的连接型组件。
- 纯逻辑功能使用固定向量、往返转换、边界输入和协议编解码测试。

### 视觉验证

- 生成工具页面截图到 `target` 下的审查目录，不提交审查产物。
- 全部工具检查正常和最小尺寸；代表性布局覆盖浅色/深色主题及简体中文/English。
- 主框架与用户效果图对照检查品牌区、搜索、导航层级、顶部栏、工作区边界和状态栏。

### 完成验证

- `mvn test`：全部测试通过，失败数为零。
- `mvn package`：Java 8 目标完整打包成功。
- 检查 `git diff`，确认没有测试配置、临时安全库、凭据、截图或视觉辅助文件进入提交。
- 对照 44 项审查矩阵确认每个工具都有结果；真实外部服务成功路径明确标记为未在本环境执行。

## 验收标准

1. 44 个工具入口全部存在、可导航、可惰性创建且关闭时不阻塞主窗口。
2. 可离线验证的核心功能和边界路径拥有自动化证据；发现的问题均有回归测试。
3. 连接型工具在无真实环境时能正确处理参数错误、连接拒绝、取消和资源关闭。
4. 主框架按效果图完成共享细节调整，同时保留安全库操作的现有位置。
5. 默认与最小窗口下，全部工具的关键操作可达；浅色/深色和中英文壳层无明显布局破坏。
6. 不删除功能，不破坏现有配置和已保存数据格式，不降低安全库保护。
7. 完整测试与打包通过，并输出一份包含修复项、验证证据和外部环境限制的最终报告。
