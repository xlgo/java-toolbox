# 批量端口扫描与网络诊断改造规划

状态：第一批已实现（2026-10-17）。功能复查后已补 IPv6 段/CIDR、末尾通配符、TXT 导入、命名方案和单端点诊断入口；第二批其余内容保留规划。本文保留原设计依据和验收标准，最终行为见 [使用指南](../../port_scanner_guide.md)及 [复查记录](../../reviews/2026-10-17-port-scanner-audit.md)。范围以现有 `port.scanner`（端口扫描与网络诊断）为主，保留工具 ID 和导航位置。

## 现有问题与代码证据

| 现状 | 实际影响 | 位置 |
|---|---|---|
| 目标输入直接作为一个主机交给 Socket | 不能展开 IP 段、CIDR 或多个目标 | `PortScannerPanel.startScan/probePort` |
| 三组预设总共约 18 个端口，文案与实际数组还有差异 | 用户难以覆盖常见服务，也难以确认实际扫描了哪些端口 | `buildConfigCard/parsePorts` |
| 解析器已接受逗号/分号端口列表，但没有示例，错误直接忽略 | 功能难发现，输错端口仍可能显示扫描成功；重复端口重复探测 | `parsePorts` |
| 预设和自定义是互斥单选项 | 无法使用“数据库组 + 另外几个业务端口” | `togglePortSelectionUI` |
| 结果只有端口，没有目标主机列 | 扩展多主机后无法辨认每一行属于谁 | `buildResultCard` |
| 所有 IOException 都显示 Closed | 超时、解析失败、主机不可达会被误判为端口关闭 | `probePort` |
| fixed pool 使用无界任务队列，调度器一次性提交全部端口 | 扩展为主机×端口后容易积压大量任务和对象 | `startScan`、`DaemonThreads.fixed` |
| 每个结果单独 invokeLater，全量塞入 DefaultTableModel | 大任务会挤占 Swing 事件线程和内存 | `probePort` |
| 停止中断线程池，但没有主动关闭正在连接的 Socket | 停止时仍可能等待连接超时 | `stopScan/probePort` |
| 复制结果只有端口，缺少目标与状态上下文 | 多主机结果无法直接复用 | `copyOpenPorts` |

保留已有扫描代次隔离机制，避免停止后重启时旧结果污染新任务。新的单元测试需覆盖该行为，目前没有独立的端口扫描测试文件。

## 第一批：完整的批量 TCP 扫描

### 1. 目标表达式

目标框支持单行粘贴和“批量编辑”弹窗，多条以逗号、分号、空白或换行分隔。示例：

```text
192.168.1.10
192.168.1.10-50
192.168.1.250-192.168.2.20
10.20.30.0/24
server-a.example.internal
2001:db8::10
```

- IPv4 支持单个地址、同网段末段简写、完整起止地址以及 CIDR；保留单主机名和单 IPv6 地址能力。
- 独立“排除目标”输入支持同样的 IPv4 表达式，如排除网关、某段地址。排除在规范化和域名解析后作用于最终 IP 集合。
- 合并重复 IP 和重叠区间，端点包含在范围内；反向范围、非法掩码、越界 IPv4、疑似带端口的 IPv4 输入应明确报错，禁止静默跳过。`server-a` 这类主机名不能误判为 IP 范围。
- CIDR 输入包含主机位时，预览其规范化后的网段。例如 `192.168.1.23/24` 归一化为 `192.168.1.0/24`。
- CIDR 默认取常规可用主机：`/24` 为 254 个；提供“包含网段首尾地址”选项。`/31` 保留两个地址、`/32` 保留一个地址。显式输入起止范围时严格按用户给定的两端取值，不另外删去 `.0` 或 `.255`。
- 域名每次任务解析一次，保存原输入与解析 IP 对应关系；同一地址的端口探测去重。解析失败按主机汇总，不为它生成数千条端口失败。
- 大段地址先做区间运算和数量校验，再惰性迭代，禁止展开 `/0` 后才判断是否超限。预览不应在用户每次键入时触发 DNS 查询。

第一批覆盖用户日常输入的 IPv4 段；IPv4 通配符、IPv6 CIDR/范围和 TXT 文件导入在第二批扩展同一个解析层。

### 2. 任意端口集合与组合预设

取消预设/自定义二选一，采用“勾选预设组 + 自定义追加 + 排除端口”三者合成。端口框同时接受单端口、列表和范围：

```text
22,80,443,2379,2380,8080-8085,9092,9093
```

上例得到 13 个唯一端口。支持空白、换行及中英文逗号/分号分隔；统一为排序后的 1–65535 端口集合。非法项指出所在条目，反向范围直接报错，所有输入校验通过后才启动扫描。预设与自定义重叠只扫描一次。

界面提供“常用组合”“全部 TCP 端口（1–65535）”快捷项，以及“保存为我的端口组”。保存的自定义组可以重命名、编辑和删除。组标签展示实际唯一端口数，展开能看完整列表；不再靠按钮文案维护另一份端口数组。

首批内置组建议如下，端口数据统一放入项目自维护资源，界面和服务提示共用来源：

| 预设组 | 初始端口候选 |
|---|---|
| Web / 应用 | 80,443,8000,8008,8080,8081,8088,8443,8888,9000 |
| 数据库 | 1433,1521,3306,5432,9042,27017,50000 |
| 缓存 / 搜索 | 6379,6380,9200,9300,11211 |
| 消息 / 注册协调 | 2181,2379,2380,4222,5671,5672,6650,8500,8848,9092,9093,9876,15672 |
| 远程 / 文件访问 | 21,22,23,135,139,445,3389,5900 |
| 邮件 / 目录 | 25,110,143,389,465,587,636,993,995 |
| 容器 / 可观测性 | 3000,4317,4318,5601,6443,9090,9100,10250 |

这些分组是可编辑的探测起点。端口对应的名称只作为“常见用途提示”，实际服务需要后续协议验证；开放某个端口不能直接断言运行了某种产品。

### 3. 扫描计划和调度

开始前在页面内展示“唯一目标数 × 唯一端口数 = TCP 探测数”，无需额外确认弹窗。例如 `/24` 默认 254 台、上述 13 个端口，共 3,302 次探测。包含排除后的数量、DNS 待解析数和预计耗时；耗时估算明确受网络响应、超时和速率设置影响。

建议初始配置：连接超时 500 ms、全局并发 64、单主机并发 8、每秒最多启动 200 次连接；并发、超时与速率均可设置。提供任务预算，默认最大 4,096 个目标、100 万次探测；高级设置可提高，初始产品上限建议 65,536 个目标和 1 亿次探测，最终数值结合基准验证调整。超预算时在开始前给出数量和超限原因。

- 主机与端口使用惰性迭代，不创建完整笛卡尔积任务列表。总数和进度计数使用 long，并检查乘法溢出。
- 使用有界工作队列和回压，待执行队列控制在全局并发的约两倍。轮转不同主机，只提交满足单主机并发限制的任务，避免一台慢主机阻塞整个网段。
- 工作线程内使用 TCP connect；记录 active sockets。停止时先阻止调度，再主动关闭连接并清理队列，最后结束本次会话。
- 不以 Ping 成功作为端口扫描前提。主机没有返回 ICMP，不足以决定跳过其 TCP 端口。
- 结果通过有界队列传递，UI 每 100 ms 批量接收，上限每批约 500 条；队列满时回压，不静默丢结果。
- DNS 使用独立、有界的解析池。原生 DNS 调用不可中断时，旧结果通过会话 ID 丢弃；不等待旧解析才能更新界面，也不通过每次新建线程绕过解析池上限。

### 4. 结果、进度和导出

结果至少包含：原目标、实际 IP、端口、协议、状态、耗时、常见用途提示、错误原因。TCP 建连耗时不能直接当作 Ping RTT，列名改为“连接耗时”。

状态分为：开放、连接失败、超时、网络/主机不可达、解析失败、其他错误、已取消。底层若能提供明确的拒绝错误码，可进一步标记“连接被拒绝”；JDK 没有可靠结构化原因时，ConnectException 保留为连接失败并显示原始原因，不能靠英文错误文案猜测。超时不能标为已关闭或确定的防火墙拦截。

- 左侧按主机汇总已探测数、开放端口数和异常；右侧为该主机或全部主机的明细。
- 默认显示开放结果，提供“全部状态”、目标/端口/状态筛选和服务提示搜索。
- 同时显示目标进度和探测进度，例如“主机 12/254，探测 156/3302，开放 18，超时 4”。停止后保留已完成结果和实际完成数，未执行任务不算关闭。
- 一键复制为 `IP:端口`；IPv6 使用 `[IPv6]:端口`。支持当前筛选结果及全部结果的 CSV/JSON 导出，保留类型、状态、时间和本次扫描参数。
- 结果表分页展示，建议每页 500 行；全量结果写入本次会话的临时 SQLite 存储，复用项目已有 SQLite JDBC。单写入者批量落库，查询/导出在后台执行，避免把百万条行对象堆进 Swing 模型。
- 临时缓存放在应用缓存目录，以本次会话标识管理；设置缓存大小预算，触顶时有明确的“结果存储已满”结束状态。应用退出清理本次临时文件，长期保存由用户显式导出。缓存只记录扫描元数据，不采集业务内容。
- “清空”在扫描执行中禁用；再次扫描创建新会话。旧回调、进度或结束事件都不能覆盖当前结果。

### 5. 界面安排

页面上方保留紧凑目标/端口摘要以及开始、停止、预览计划。批量目标编辑、端口组编辑和高级参数各有独立入口，复杂配置可折叠；主要空间留给主机汇总和结果表，窄窗口允许动作换行。

常见输入示例直接展示在输入框下方或占位提示中，包括 IP 段和离散端口。当前超时、并发与端口组可记住；目标列表和排除范围只有显式保存扫描方案时持久化，打开工具不自动执行历史任务。

## 第二批：诊断闭环与可复用配置

在第一批稳定后增加：

1. 导入 TXT 目标列表、IPv4 通配符与有界 IPv6 CIDR/范围；保存命名扫描方案（目标、排除、端口组、超时、并发和速率）。
2. 可选的反向 DNS 和主机标签，解析结果在会话中缓存。
3. 对选中的开放结果执行 TLS 证书检查、HTTP 状态/耗时或有界 Banner 读取。保留原主机名供 SNI/Host 使用，不只传递解析 IP。
4. 从结果行进入现有 `net.diagnostics`，复用 `NetDiagnosticsService`；批量诊断共享相同的目标解析、调度和会话取消机制。
5. 结果快照比较，展示新增开放端口、消失端口和状态变化；重试只针对用户选择的失败项，并形成可区分的新一轮结果。

第一批扫描协议为 TCP connect。UDP 需要按协议定义探测与不确定状态，作为后续独立交付切片；不能直接复用 TCP 的开放/关闭判定。

## 实现拆分与交付顺序

| 层 | 计划组件 | 职责 |
|---|---|---|
| domain | `ScanTargetParser`、`PortExpressionParser`、`ScanPlan`、`ProbeOutcome` | 表达式语义、区间并集/排除、数量预算、状态模型；不依赖 Swing |
| application | `PortScanService`、`ScanSession`、`ScanPlanResolver` | DNS 解析编排、公平调度、速率限制、进度、取消与结果队列 |
| infra/network | `TcpConnectProbe`、`ScanResultRepository` | Socket 连接和主动关闭、会话 SQLite 存储、查询/流式导出 |
| ui | 重构 `PortScannerPanel` | 输入与预览、配置入口、主机/端口列表、过滤、批量刷新和导出 |
| resources | 自维护端口组资源、三份语言资源 | 可组合预设、用途提示和完整本地化 |

按以下顺序实施，第一批完成全部步骤后再作为完整功能交付：

1. 解析器与计划模型，锁定输入示例和数量语义。
2. 有界扫描会话和可取消的 TCP 探测，使用本地测试端口验证状态与资源释放。
3. 组合端口组、结果存储与查询/导出。
4. 面板重构、模板持久化和批量 UI 更新。
5. JDK 17 定向及全量 verify、界面检查、文档与最终 JAR 验证。

保留 `ManagedResourceOwner` 关闭契约，复用具名守护线程工厂，但新扫描服务自行使用有界队列；不能直接沿用当前 `DaemonThreads.fixed` 的无界队列。保留工具稳定 ID `port.scanner`，新增 `portscan.*` 国际化键，不增加硬编码中文基线。

## 验收标准

| 场景 | 应满足的结果 |
|---|---|
| `192.168.1.10-20`，端口 `22,80,443,8080-8082` | 11 个目标、6 个唯一端口、66 次计划探测 |
| `192.168.1.0/24`，端口 `22,80,443,2379,2380,8080-8085,9092,9093` | 默认 254 个目标、13 个唯一端口、3,302 次探测 |
| 单 IP 与 CIDR/区间重复，预设与自定义端口重复 | 去重，排除先影响最终目标/端口集合，再计算总数 |
| `/31`、`/32`、CIDR 首尾地址选项 | 分别保留 2/1 个地址，切换选项后预览数与实际任务数一致 |
| 非法 IP、`65536`、`abc`、反向范围、超大网段 | 精确指出条目和原因，未启动探测 |
| 测试服务监听的端口、未监听的本地端口、可控超时探针 | 分别显示开放/连接失败及原因/超时；不把后两者合并。注入明确拒绝码时验证额外细分 |
| 一个域名解析失败，其他 IP 正常 | 单独显示解析失败，其他目标继续；总数按最终解析计划结算 |
| 停止后立即启动新任务 | 旧结果和完成事件不影响新任务；活跃 Socket 主动关闭 |
| 大计划 | 在首个连接前完成预算判断；任务队列、内存结果批次有明确上限，EDT 不做网络访问 |
| 导出多主机结果 | 每行包含目标、实际 IP、端口、状态和连接耗时；全部导出不受当前页和开放过滤限制 |
| 窗口关闭 | 当前扫描、解析回调、缓存写入和后台查询停止或隔离，清理本次会话资源 |

测试以 loopback 本地服务与可注入探针为主，不扫描用户未指定的外部网段。性能记录需包含目标数、端口数、超时、并发、速率、内存峰值和停止耗时，避免只凭“跑得快”判断完成。

## 语义依据

- [JDK 17 Socket](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/net/Socket.html)：连接超时、Socket 关闭与异常边界；状态模型应区分连接结果。
- [Nmap 端口状态说明](https://nmap.org/book/man-port-scanning-basics.html)：观测状态依赖探测方式和网络路径；简单 TCP 超时不能确认端口已关闭。本项目按实际 TCP 连接结果设计状态，不照搬其全部扫描类型。
- [RFC 3021](https://www.rfc-editor.org/rfc/rfc3021.html)：点对点 `/31` 的两个地址可以是主机地址；地址展开不能一律删除 CIDR 首尾。默认是否包含常规网段首尾属于本工具的明确配置策略。
