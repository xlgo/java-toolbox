# 微信通讯录与群发指南

在 Windows 微信 4.x 完成登录后，打开工具箱“微信群发与通讯录”的“通讯录管理”页，点击“自动读取通讯录”。无需切换微信页面、选择第一个好友、配置点击间隔或停止使用鼠标。

工具自动识别微信配置指定的数据目录，兼容 Documents 重定向和非默认存储位置。读取程序用数据库页的 HMAC 验证当前登录账号，避免把旧账号目录误当成当前账号。读取本地个人联系人及企业微信联系人，排除本人、已删除记录、群聊、群成员缓存及公众号；同名联系人按稳定 UserName 保留。个人记录不要求 flag 的第 2 位为 1，避免漏掉 flag=1 的联系人。

表格展示昵称、微信号、备注和标签。Excel 导出还保留性别、稳定 UserName 和头像链接，可原样导回；头像下载仍需选择联系人后单独执行。读取结束前不替换当前表格，停止或错误会保留原列表。

## 环境与读取方式

- Windows，已登录微信 4.x。
- 64 位 Python 3.11 或更新版本，包含 SQLite 内存反序列化支持。自动检测 python、py -3、python3。
- 通讯录读取的本地 AES 解密使用 cryptography，缺少时助手自动通过当前 Python 的 pip 安装。通讯录读取不包含 OCR 模型，不依赖 UIAutomation 或 Tkinter。

运行中的微信进程只以读权限打开；当前通讯录文件和 WAL 也只读取。助手验证每页认证值、WAL 头及帧校验和，只合并完整已提交事务，在内存 SQLite 中读取联系人。密钥与解密数据库不写入磁盘，不修改微信进程、客户端文件或系统无障碍状态，也不读取聊天记录。

本机微信 4.1.13.65 初次读取 588 条，但随后按具体联系人核查发现筛选漏读；已修正为读取 665 个唯一个人联系人。数量与客户端列表一致不能证明名单完整。本地记录的昵称和备注可能与手机端或当前客户端显示不同，支持按微信号和稳定 UserName 搜索。未来微信版本修改数据库结构或读取参数时可能需要适配；不能读取时会明确报错，不把失败当成空通讯录。

## 命令行

```powershell
python tools/wechat_export.py
# 可选：包含数据库中的群聊和公众号
python tools/wechat_export.py --all-contacts
```

输出为 UTF-8 JSON Lines：status、contact、complete 或 error。仅收到 count 与联系人数量一致的 complete 才认为读取成功。工具箱通过私有进程管道消费结果，不把联系人行打印到日志。

“导入外部通讯录文件”和剪贴板导入继续可用。WeChatContactReader.readContacts 也保留用于读取用户提供的已解密旧版 Contact/rcontact SQLite 文件；该旧接口不会自动解密原文件。

## 文本群发

1. 在“群发助手”页点击“群发配置”设置发送方式和间隔，默认是“文本后台核验”；图片附件位于同一弹窗的“全局图片”页。关闭弹窗会保留设置，配置和附件不再占用待发列表空间。从通讯录添加联系人，或填写准确的微信号、稳定 UserName、唯一昵称/备注；每行填入要发送的文本。
2. 确认微信已设置为 Enter 发送，点击“开始群发”。定位时程序会短暂拉起微信并打开聊天，核对接收人和输入内容。之后微信可最小化，也可由其他应用保持前台，不需要人工逐条确认。
3. 观察每行状态和日志。停止操作会取消后续任务并恢复窗口，助手退出前不能启动下一批。

待发列表占据主页面约四分之三宽度，可拖动与日志之间的分隔条调整。选中行后点击“删除选中”或按 Delete 从列表移除，Ctrl/Shift 支持多选；单元格编辑时 Delete 仍用于删除文字。发送执行中不允许删除或修改配置，停止后需等助手退出再编辑列表。

文本模式需要 64 位 Windows、已登录的微信 4.x、64 位 Python 3.11+ 与 uiautomation、cryptography；缺少的 Python 依赖自动安装。已在微信 4.1.13.65 实测，其他版本的控件和数据库结构需要验证。通讯录页仍然不使用 UI Automation。

发送前会用当前微信进程的密钥验证通讯录和消息数据库，唯一识别当前账号，再把微信号或 UserName 映射到联系人。聊天打开后读回输入框标题和完整文本；同名联系人、无法唯一对应的搜索结果、已有草稿都会跳过，草稿不会覆盖。名称冲突检查也包含本地未删除的非好友和公众号记录，避免最近会话标题相同导致错选。没有自定义微信号时使用数据库中的唯一显示名称搜索，不直接用微信无法识别的内部 wxid 搜索。

文本通过 UI Automation ValuePattern 写入及读回；最终 Enter 事件仅投递给已定位的微信窗口，不使用全局键盘事件或剪贴板粘贴。最近聊天和搜索结果都通过控件定位；搜索结果的 Select 方法在实测版本无效，因此用控件边界点击，并再次验证实际聊天标题，不将点击或接口返回值当成发送成功。

结果核验只读解密数据库的内存快照，核对发送前基线之后的新记录、目标会话、完整文本、文本消息类型、当前账号的发送者映射及本机来源。每个分片独立查询 Name2Id，不能固定发送者数值 ID。等待核验最长 20 秒，状态含义如下：

| 状态 | 含义与后续行为 |
|---|---|
| 已确认发送记录 | 唯一的新发出记录满足 status=2 且服务器 ID 大于零；不代表对方已收到或已读 |
| 待确认 | 已出现本机新发出记录，但在等待期内没有符合条件的服务器确认记录 |
| 未确认 | 已尝试投递，但未查到匹配记录、查到多个匹配记录，或触发后停止/异常；需要检查实际会话 |
| 未发送 | 接收人、草稿、控件或输入校验失败，尚未触发发送 |
| 已停止（未发送） | 停止发生在发送前 |
| 已触发（未核验） | 兼容模式仅执行了前台快捷键操作，未核对消息数据库 |

已确认、待确认、未确认和兼容模式已触发的行，再次开始或切换模式时都会跳过。不会通过盲目重发来解决超时。确认实际会话后需要重新发送时，手动添加新任务行；清空或重新导入列表不会保留上一批的去重状态。当前每批最多 1,000 行、每条最多 10,000 字符，间隔 500–60,000 毫秒；本地数据库及 WAL 的单文件快照上限为 128 MiB，超过上限或结构不支持会报错。

## 窗口状态与兼容模式

发送助手在窗口所属进程上持有独占锁。当前只接受一个微信主窗口及可唯一验证的账号；多个账号同时登录时请只保留待发送实例。微信隐藏到托盘时使用客户端唤醒方式恢复，导航后再次核对输入框，结束时恢复原先窗口位置、显示状态和前台应用；控件点击后尽量恢复鼠标位置，若用户已移动鼠标则不覆盖。

微信默认未暴露 Qt 控件树时，助手会验证磁盘模块及运行中的指令、唯一可写数据地址和原始值，临时开启 Qt 无障碍状态，正常结束或停止后恢复原值；不修改客户端文件，不注入 DLL，不修改通讯录或消息数据库。助手被外部强制终止时无法执行恢复流程，可退出并重新启动微信。通讯录读取助手继续只读访问进程，不进行此状态切换。

图片、全局图片和 Ctrl+Enter 使用“兼容发送（文本/图片）”，此模式保留原有 Robot 快捷键操作，需要微信在前台，无法核验结果。文本模式检测到图片路径或已启用的图片附件会要求切换模式。文本模式的当前实现不支持锁屏、无人登录的桌面或 Mac。

## 实现来源

Qt 状态与控件结构资料参考社区项目 [wechatauto-replica 的 uia_driver.py](https://github.com/fanyuantaier/wechatauto-replica/blob/main/wechatauto/uia_driver.py)，WCDB 密钥结构参考 [db.py](https://github.com/fanyuantaier/wechatauto-replica/blob/main/wechatauto/db.py)。数据库页认证及已提交 WAL 边界依据 [SQLCipher 设计](https://www.zetetic.net/sqlcipher/design/)和 [SQLite 文件格式](https://sqlite.org/fileformat2.html#walformat)。本项目使用独立助手实现联系人校验、定向发送、只读快照和事件协议，不依赖上述项目运行。

## 验证

```powershell
python -m unittest discover -s tools/tests -v
mvn -B -o verify
```

Python 回归覆盖页认证、错误密钥、WAL 提交边界、取消解密、联系人分类、字段保留和原文件不变，以及旧记录/收到的记录/同步记录排除、发送者分片映射、服务器 ID 与状态、草稿保护、搜索定位及重复记录。Java 回归覆盖完成协议、Excel 往返、表格编辑提交、防重复发送和停止等待。真实测试和限制见 [群发验证记录](reviews/2026-10-13-wechat-bulk-send.md)。
